  package "Rule-based модуль" as RuleMod {
    component "RuleBasedFraudProcessor" as RBProc

  }
  package "Random Forest модуль" as RFMod {

  }
}

RBProc .up.|> ProcI : реализует
RBInterp .up.|> InterpI : реализует
RBProc *-- RC : композиция

RFTrain .up.|> TrainI : реализует
RFProc .up.|> ProcI : реализует
RFInterp .up.|> InterpI : реализует

note top of User
  <b>Две парадигмы:</b>
  правила и supervised (RF).
  Три интерфейса ядра реализованы.
  
  Все реализации работают со списками:
  • process(List<FraudDetectionInput>) → List<FraudDetectionOutput>
  • train(List<FraudDetectionInput>) → void
  • interpret(List<FraudDetectionOutput>) → Any
end note

note bottom of RuleMod
  <b>Rule-based:</b> не требует обучения.
  Только Processor + Interpreter.
  Конфигурация из RuleConfig.
end note

note bottom of RFMod
  <b>Random Forest:</b> supervised.
  Trainer + Processor + Interpreter.
  Модель сохраняется/загружается
  из файловой системы.
end note
