  + process(input: List<ProcessorInput>) : List<ProcessorOutput>
}

  + interpret(output: List<ProcessorOutput>) : Any

' ========= Основные классы =========
class RuleBasedFraudProcessor <<User>> {
  - config: RuleConfig
  - rules_triggered: dict
  ..
  + process(input: List<FraudDetectionInput>) : List<FraudDetectionOutput>
  - check_word_count(ling: dict) : bool
  - check_fog_index(ling: dict) : bool
  - check_sentiment(ling: dict) : bool
  - check_passive_voice(ling: dict) : bool
  - check_uncertainty(ling: dict) : bool
  - aggregate_results() : (int, List[str])
}

note bottom of RuleBasedFraudProcessor
  <b>Реализация интерфейса Processor</b>
  для Rule-based детектора.
  
  Получает список всех входов.
  
  <b>Для каждого элемента списка:</b>
  1. Извлекает linguistic_features
  2. Проверяет каждое правило
  3. Если сработало ≥ min_rules_triggered
     → помечает как Fraud
  4. Формирует FraudDetectionOutput
  
  <b>Возвращает:</b> List<FraudDetectionOutput>
  
  <b>Игнорирует</b> tfidf_features и
  combined_features (использует только
  лингвистические признаки).
  
  <b>Преимущество:</b> не требует
  предварительного обучения,
  не загружает модели из файлов.
end note

class RuleBasedFraudInterpreter <<User>> {
  + interpret(output: List<FraudDetectionOutput>) : Any
  ..
  - format_alert(output: FraudDetectionOutput) : str
  - log_to_console(report_id: str, rules: List[str]) : void
}

note bottom of RuleBasedFraudInterpreter
  <b>Реализация интерфейса Interpreter</b>
  
  Получает ВСЕ результаты сразу.
  
  <b>Постобработка для каждого результата:</b>
  • Форматирует читаемое объяснение
  • Логирует в консоль/файл
  
  <b>Агрегированная аналитика:</b>
  • Сводная статистика срабатывания правил
  • Какие правила срабатывают чаще всего
  • Распределение количества сработавших правил
  • Сравнение с порогами из конфигурации
  
  <b>Для Production:</b> расширяется
  отправкой алертов в Telegram/Slack/БД.
  
  Получение всего списка позволяет
  строить сводную статистику по всем
  документам.
end note
